# codex-long-task-manager

让Codex连干4小时不跑偏的skill。4个外置状态 + 6个检查点 + 验收合同 + 人工门。

## 安装

把 `SKILL.md` 复制到你项目的 `.codex/skills/` 目录下：

```bash
mkdir -p .codex/skills/codex-long-task-manager
cp SKILL.md .codex/skills/codex-long-task-manager/SKILL.md
```

或让Codex自己装：

```
帮我安装这个skill：https://github.com/songlanglang/codex-long-task-manager
```

## 使用

| 命令 | 做什么 |
|---|---|
| 启动 | 生成GOAL.md合同 + 确认4个外置状态 + 列出检查点和人工门 |
| 检查 CP1~CP6 | 在某个检查点停下来时自检，逐条报告通过/不通过 |
| 结束 | 跑完端到端演示后最终验收，对照合同四段逐条对 |

## 4个外置状态

| 状态 | 存哪 | 为什么 |
|---|---|---|
| 代码配置 | git | 跑偏了能diff、跑飞了能checkout |
| 长期规则 | AGENTS.md | 跨会话的规矩，写一次受益一百次 |
| 当前进度 | GOAL.md | 每轮更新，新对话读一遍就接着干 |
| 验收证据 | evidence/ | 不让它口头说"做完了"，证据落文件它编不了 |

## 6个检查点

| 检查点 | 看什么 | 判断标准 |
|---|---|---|
| CP1 方案冻结 | 分几步、输入产出、第一步对不对 | 粒度合理 + 第一步奔目标 |
| CP2 数据协议 | 字段映射、读写格式 | 写到文档里了 = 通过 |
| CP3 资源接入 | API能调通、文件能读、数据结构对 | 不只是能调通，还要字段齐全 |
| CP4 review修复 | review标准、问题清单、diff | 三条标准答完 + 贴diff |
| CP5 环境联调 | 换环境、干净环境跑通 | 改了一半的环境不算 |
| CP6 端到端演示 | 完整跑一遍、没加假设、合同逐条对 | 全通过 = 活算完 |

## 人工门

遇到这些操作必须停下来等用户确认：删数据、合并代码、上线发布、花钱、不可逆操作。

## 不适用

30分钟以内的短活、单文件小改动、不涉及线上环境——直接干，别套这套流程。
